# Kookmin University Autonomous Driving Contest 2025

## 1. Project Overview

This repository contains the ROS 2 source code for the 2025 Kookmin University Autonomous Driving Contest. The software is designed to perform lane-keeping, dynamic obstacle avoidance, and mission-based driving.

## 2. Core Concepts

This autonomous driving system is built upon three core concepts:

### Concept 1: Robust Perception with YOLO

Reliable environment perception is the foundation of this project. We use a **YOLOv10n model** to detect key objects such as vehicles, traffic lights, and lane markers from the camera feed. This model provides the initial, high-level understanding of the scene, which is then refined by other nodes to create a detailed world model.

### Concept 2: Integrated Judgement via LiDAR-Camera Fusion

To make intelligent decisions, the system fuses data from multiple sensors. Based on a precise **LiDAR-Camera calibration**, 3D LiDAR point clouds are projected onto the 2D image. This allows the system to gain accurate distance and position information for objects detected by the camera. This fused data enables the vehicle to understand complex scenarios and execute advanced maneuvers like overtaking and emergency stops.

### Concept 3: Stable Control with the Stanley Method

For vehicle control, we employ the **Stanley method** for robust and smooth lane-keeping. This non-linear control law calculates the required steering angle by considering both the vehicle's heading error and the cross-track error relative to the target path. This results in stable and human-like driving behavior, especially on curved roads.

## 3. System Architecture & Data Flow

The system follows a standard pipeline architecture for autonomous driving:

**Sensors → Perception → Judgement → Control → Actuators**

1.  **Sensor Nodes** (`xycar_device`): Drivers for Camera, LiDAR, IMU, and Ultrasonic sensors publish raw data.
2.  **Perception Nodes** (`cam`): 
    - `yolo_node` detects objects in the image.
    - `centerlane_tracer` creates a smooth center line from YOLO detections.
    - `Lane_Detector` identifies the left and right lane boundaries.
3.  **Judgement Node** (`cam`):
    - `target_lane_planner` fuses all sensor data to understand the environment, determines the driving state (e.g., follow, overtake), and sets the target path.
4.  **Control Node** (`cam`):
    - `Integrated_Stanley_Controller` calculates the final steering and speed commands based on the target path and obstacle information.
5.  **Actuators**: The commands are sent to the vehicle's motor and steering servo.

## 4. Node Descriptions

### 4.1. Perception & Judgement (`cam` package)

- **`Camera_Publisher.py`**: Initializes the camera, applies fisheye correction, and publishes the calibrated image stream.
- **`yolo_node.py`**: Runs a YOLOv10 model on the image stream to detect vehicles, traffic lights, and lane markers.
- **`centerlane_tracer.py`**: Processes YOLO's `center_line` detections to trace a clean, continuous, and smooth drivable path, which it publishes as a `Curve` message.
- **`Lane_Detector.py`**: Transforms the image to a Bird's-Eye-View (BEV) and uses computer vision techniques to detect left and right lane boundaries, publishing the result as a `XycarState` message.
- **`target_lane_planner.py`**: The brain of the vehicle. It fuses LiDAR, Camera, and Ultrasonic data to build a comprehensive world model. It runs a state machine to make high-level decisions (e.g., follow lane, overtake obstacle, emergency stop) and publishes the vehicle's state and target path.
- **`SignDetector.py`**: A simple mission node that detects a green traffic light from YOLO detections to trigger the start of a mission.

### 4.2. Control (`cam` package)

- **`Integrated_Stanley_Controller.py`**: The primary driving controller. It takes the target path and obstacle information to calculate the precise steering angle and speed using the Stanley method, sending the final commands to the motor.

### 4.3. Cone Mission (`mission_cone_drive` package)

- **`preprocessing_node.py`**: Processes raw LiDAR data using DBSCAN clustering to identify potential cones.
- **`path_planning_node.py`**: Groups the detected cones into left/right lines and generates a smooth path between them using splines.
- **`pure_pursuit_node.py`**: A path-tracking controller used specifically for the cone mission. It follows the path generated by the `path_planning_node`.

### 4.4. Hardware Drivers (`xycar_device` package)

- This package contains nodes (`xycar_cam`, `xycar_imu`, `xycar_lidar`, `xycar_ultrasonic`) that interface directly with the vehicle's hardware and publish their data as ROS 2 topics.

## 5. YOLOv10n Model Training

The YOLOv10n model used for object detection was trained from scratch on a custom dataset. The dataset was created from ROS2 Bag files using a semi-automatic labeling approach. This process was facilitated by the **ros2yolo-toolkit**.

For more details on the toolkit and methodology, please refer to the repository:
[kdh10086/ros2yolo-toolkit](https://github.com/kdh10086/ros2yolo-toolkit.git)

## 6. Setup and Launch

### Prerequisites
- ROS 2 (Humble or later recommended)
- Python 3, OpenCV, PyTorch

### Build
Navigate to the workspace root (`kookmin_contest_25_ws`) and run:
```bash
colcon build --symlink-install
```

### Launch
Source the setup file (`source install/setup.bash`) before running any of the following commands.

#### Live Environment

- **Full Mission (Cone Drive + Lane Keeping + Obstacle Overtake)**
  ```bash
  ros2 launch mission_cone_drive drive.launch.py
  ```

- **Lane Keeping + Obstacle Overtake Mission Only**
  ```bash
  ros2 launch cam obstacle.launch.py
  ```

#### Bag File (Simulation) Environment

- **Full Mission from Bag File**
  ```bash
  ros2 launch mission_cone_drive bag_test_all.launch.py
  ```

- **Lane Keeping + Obstacle Overtake Mission Only from Bag File**
  ```bash
  ros2 launch cam bag_test.launch.py
  ```
